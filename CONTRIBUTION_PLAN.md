## Overall Strategy

My strategy was to focus on small, well-defined tasks that would increase my chances of having Pull Requests merged. I targeted documentation improvements (docstrings and README enhancements) because they are valuable to maintainers but low-risk for me as a contributor.

**Key steps I followed:**

1. **Identify `good-first-issue` labels** – I searched for repositories that explicitly label beginner-friendly tasks.
2. **Communicate first** – I commented on each issue to signal my intent before starting any work.
3. **Follow project conventions** – I ensured my contributions matched existing styles (e.g., Google-style docstrings).
4. **Keep PRs focused** – Each PR addressed a single, specific change to make review easier.
