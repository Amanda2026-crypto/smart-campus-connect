# Reflection

## Challenges in Selecting and Customizing the Template

**Challenge 1: GitHub templates have changed** - The assignment mentioned "Basic Kanban" and "Automated Kanban," but GitHub now shows "Kanban," "Team planning," and "Bug tracker." I adapted by selecting "Kanban" which has the same auto-close feature.

**Challenge 2: Adding meaningful columns** - I needed to add 2+ columns. I added Testing (for quality assurance) and Blocked (for dependencies like US-010 depending on US-009).

**Challenge 3: Setting WIP limits** - As a solo developer, I set In Progress limit to 2 and Testing limit to 1 to avoid context switching.

## Comparison to Other Tools

| Tool | Pros | Cons |
|------|------|------|
| **GitHub Projects** | Integrated with code, free, automation built-in | Limited reporting features |
| **Trello** | Very easy to use, visual | No code integration, automation requires paid features |
| **Jira** | Powerful, detailed reporting | Too complex for solo developer, expensive |

## Lessons Learned

GitHub Projects is sufficient for solo Agile development. The Kanban template with custom columns (Testing, Blocked) meets all my Sprint 1 needs. The auto-close automation saves time and ensures completed work is properly tracked.
