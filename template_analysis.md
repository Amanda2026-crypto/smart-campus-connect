# Template Analysis and Selection

## Comparison Table

| Template | Columns | Automation Features | Suitability for Agile |
|----------|---------|---------------------|----------------------|
| **Kanban** | Todo, In Progress, Done | Auto-closes issues when moved to Done | High - perfect for sprint tracking |
| **Team planning** | Backlog, Ready, In Progress, In Review, Done | None | Medium - better for multi-team planning |
| **Bug tracker** | Todo, In Progress, Done | None | Low - designed for bugs, not user stories |

## Selected Template: Kanban

### Justification

I selected the **Kanban** template because:

1. **Automation** - It auto-closes issues when moved to Done, saving manual work for a solo developer
2. **Sprint alignment** - Todo → In Progress → Done matches my Sprint 1 from Assignment 6
3. **Simplicity** - Three core columns keep the workflow focused
4. **Customizable** - I can add Testing and Blocked columns without breaking automation

### Why Not Other Templates

- **Team planning** - Too many columns (Backlog, Ready, In Review) would confuse a solo developer
- **Bug tracker** - Designed for bug tracking, not user story management
